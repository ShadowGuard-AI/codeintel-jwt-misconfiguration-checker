The Mortar and the Token

This program reads source text for signs of faulty JSON Web Token practice, searching for an alg entry set to none, for expiration handling that is absent from a file which otherwise speaks of jwt, for encoding done with HS256, and for verification switched off, with an optional further search, switched on only by a flag, for assigned secret or key values that are short, or that match a short list of predictable words, or that consist of one of those words repeated to fill their length.

What the program does not do

PyJWT is deliberately not imported, no token is decoded, no signature is tried, no library configuration is loaded and validated, and the search is pattern matching over file contents from beginning to end. A reader who mistakes text searching for token testing will trust the result too far.

Five Patterns in the Grinding, the true invocation

python3 main.py TARGET [--verbose] [--check-secrets] [--output PATH]

The README printed usage, a bare executable name followed by the word params in brackets, omits the one argument the parser requires and cannot be run as shown. The target comes first and is not optional, and everything after it is a flag or a flag with a path of its own.

The Required Target, arguments in parser order

targetPath to the file or directory to scan. Required and positional.
--verboseTurns on debug logging.
--check-secretsEnables the search for hardcoded secrets, which otherwise does not run at all, so a scan without that flag says nothing whatever about secrets.
--outputNames a path to which results may be saved.
-hShows the help message and exits.

Output rule: the file is written only when there is something to put in it, either findings or files that could not be scanned, so after a clean run no output file appears, and its absence means clean rather than lost.

Findings and Their Limits

An alg none finding follows a written alg entry, quoted or unquoted at the key, set to the word none in either letter case. An HS256 finding follows any jwt.encode call written with that algorithm, whether the secret behind it is long or short, and is phrased in the code as a recommendation to consider stronger algorithms rather than as proof of weakness. A disabled verification finding follows jwt.decode written with verify set to False, or a verify_signature entry set to False. A directory walk descends through the tree and reads only files ending in .py, .js, .java, or .go, whereas a single file handed to the program directly is read whatever its ending may be.

A Helper Elsewhere Does Not Acquit This File

A missing expiration finding is raised per file, and only where the file mentions jwt yet nowhere contains exp or expiration, which means expiration handled in a shared helper elsewhere does not acquit a file that stays silent on the subject.

The Value Is Never Printed

A weak secret finding, under the flag, reports only the variable name, the length of its value, and whether that value matched the predictable list, and it never prints the value itself in clear, on the console or in a file.

Not Scanned Is Not Clean, and Exit One Means Look Again

A target that is neither file nor directory is refused with an error and exit 1. A file that cannot be read or decoded is reported by name as not scanned and also brings the run to exit 1, since an unread file is not a clean file. Any finding brings exit 1. A run with no findings and no failures prints that no JWT misconfigurations were found and exits 0.

Preserved record, verbatim lines and code facts

# codeintel-JWT-Misconfiguration-Checker

Scans code for common JWT (JSON Web Token) misconfigurations, such as weak signature algorithms (e.g., HS256 with insecure secret), missing expiration claims, and usage of 'none' algorithm. Validates JWT libraries configurations. - Focused on Tools for static code analysis, vulnerability scanning, and code quality assurance

## Install

`git clone https://github.com/ShadowStrikeHQ/codeintel-jwt-misconfiguration-checker`

## Usage

`./codeintel-jwt-misconfiguration-checker [params]`

## Parameters

- `-h`: Show help message and exit

- `--verbose`: No description provided

- `--check-secrets`: Enable checks for hardcoded secrets.

- `--output`: Path to save results to a file.
